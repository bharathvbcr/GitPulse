# DevMap audit and hardening

Scope: GitPulse's file, symbol, subsystem, and document maps, the shared DevCouncil visualization payload, and the browser preview. This records implementation and bounded local verification, not release or universal correctness certification.

## September 10 runtime and feedback-loop audit

This checkpoint audits the watcher → live-index queue → native refresh → CLI/logging flow and browser error classification. Earlier sections below are historical checkpoints, not current whole-workspace verdicts. Existing GitHub, status-window, and storage edits were preserved. The watcher and observer filters were already being edited when this audit began; their combined behavior was examined and tested rather than attributing all changes to this audit.

### Findings and fixes

| Finding | Evidence before the fix | Final contract |
| --- | --- | --- |
| Generated indexes feed repository refreshes | Existing durable logs contained 243 builds in the rotated file, 195 explicitly unchanged, plus 87 unchanged builds in the current file. This confirms redundant work; the logs alone cannot establish which filesystem event caused each build. | Generated `.devcouncil`, `.devmap`, and `.gitnexus` paths are filtered before debounce. Only the first component below the watched worktree is reserved. Ancestors, nested source fixtures, real Git refs, mixed events, and unclassifiable paths remain signal. |
| Path aliases are inferred from a shared suffix | A late concurrent implementation classified `/unrelated/workspace/repo/.devcouncil/index` as belonging to `/workspace/repo`. A new regression failed before correction. | Fast-path exact worktree-relative paths. Reject parent traversal before classification. Absolute aliases require matching filesystem canonical identity, with at most 64 ancestor probes; deleted leaves are supported. Real symlinks, reverse aliases, replaced aliases, relative events, and 1,000 mixed path iterations are tested. Synthetic arbitrary prefixes were removed as positive alias fixtures because they do not establish identity. |
| Observer substring matching hides real failures | A regression retained only 2 of 7 application/console/rejection failures mentioning the browser message. A 10,000-event notification storm recorded zero suppressed occurrences. | Match exact delivery-limit messages only, with no attached exception or script location. Route identifiable browser notifications through the diagnostics sink's session counter with zero persistence writes. Explicit errors and near-matches remain errors. The UI and copied report describe runtime notifications, rather than incorrectly calling all of them development reloads. |
| Busy refresh still spawns a status process | Holding the build guard and making 32 refresh attempts created a `status-calls` marker before the fix. | Skip before binary/status execution when the writer is already held. Untested availability, freshness, and compatibility facts stay false. The existing build guard still resolves races after the status check. |
| Malformed status authorizes automatic rebuilding | `{}` produced a refresh decision. Null/array bodies and missing or mistyped booleans were adversarial inputs. | Both `is_fresh` and `schema_outdated` must be actual booleans. Unavailable or incomplete status cannot authorize an automatic build and retains an explanatory reason. |
| Explicit failure is accepted after exit 0 | A fake CLI returning `{"ok":false}` passed the shared runner. | Build, status, and preview reject the explicit failure through the same runner and record the protocol failure. Existing non-JSON, error-report, timeout, incomplete-pipe, bounded-output, and redaction behavior is preserved. |
| Verification fixtures drift | The browser suite failed `all invoked commands have explicit fixtures` with `["cmd_last_fetch_at"]`; the version contract found eight current-version literals in diagnostics tests. | Supply an explicit nullable fetch-time fixture and derive diagnostic test versions from `APP_VERSION`. A new browser assertion reproduced the misleading suppression label before it was corrected. |

The observer classification follows the [Resize Observer delivery-error algorithm](https://drafts.csswg.org/resize-observer/#deliver-resize-loop-error): it creates an ErrorEvent and sets its message. An attached application exception is never treated as browser noise, even if its text is identical. Suppression is session-scoped observability, not evidence that a layout loop converged.

## Final local hardening pass

- Reproduced before fixing: refresh lost selection; layout ignored all edges; 5,000 isolated communities created 5,001 controls; offscreen geometry still submitted draw calls; undirected subsystem neighbors acquired false direction; Fit view left distant supplied coordinates offscreen; invalid coverage displayed values such as `20 of 4` or `[object Object]`; native loaders treated malformed shapes as available and parsed oversized input before rejecting it.
- Retained regressions cover those failures. The browser harness additionally verifies combined filters, paging beyond the first 30 nodes, incoming/outgoing lists, activating a root-level Swift file with Enter, and clearing selection when its node disappears.
- `Run stress checks` mounts the production Svelte/canvas implementation and measures load plus frame completion. Final stable-server measurements: sparse 320/1440 px = 176/74 ms load, 19/17 ms maximum frame; dense = 532/347 ms load, 26/30 ms maximum frame; isolated = 87/47 ms load, 18/17 ms maximum frame. Eight keyboard pan/zoom interactions are measured per case. No hot reload was enabled for this final run.
- A final server-log audit found two `ResizeObserver loop completed with undelivered notifications` errors that the initial harness did not include in its verdict. The harness now fails on browser errors and unhandled promise rejections. That stricter check reproduced the failure before the fix. Resize measurements now use a separate frame scheduler, canceled on teardown; the strict stress matrix passes after the fix. The three scheduler regressions also pass.
- Full frontend suite at the broader checkpoint: 5,028 passed / 3 failed. The failures were two ConflictEditor source contracts and its CSS-token contract (`--font-mono` and `--side-color`). Concurrent work resolved them; the final targeted recheck passes all 24 tests in those two files. This supersedes the known failures but is not a new full-suite run.
- Latest `npm run check`: zero errors and zero warnings. Production build passes with the existing large-chunk warning. `cargo clippy --manifest-path src-tauri/Cargo.toml --lib -- -D warnings` passes.
- `node scripts/vendor-crates.mjs --check --allow-drift`: no vendor-local edits, devmap-query matches upstream. Extractor and store drift belong to concurrent upstream work and were preserved.
- The four central existing implementation files (`graphPayload.ts`, `CodeGraphCanvas.svelte`, `CodeGraphRenderer.ts`, and native `viz.rs`) have 990 added / 379 removed lines against HEAD; new navigation/test/harness files and the upstream projection are separate.
